# 我的写作流水线（SKILL 骨架）

> 这份 SKILL 是**你要改的地方**：它决定这条流水线写什么、怎么写、怎么自评。
> 引擎不读它、也不管内容质量——引擎只负责"把写好的东西按草稿发出去"。
> 它与引擎的接口见 [`../../../docs/writing-pipelines.md`](../../../docs/writing-pipelines.md)。

**这一段就是"不同流水线写不同风格文章"的落点**：同一个引擎下，另一条流水线把这张表填成完全不同的值，
两条流水线互不影响。

## 1. 栏目与产出

栏目（slot）由本流水线的 [`.crosspost/schedule.json`](../.crosspost/schedule.json) 声明，
每个栏目一行：`id` / `名称` / `时间` / 命令。引擎只校验 `id` 的形状（小写字母开头），名字随你起。

产出落在 manifest 的 `dataDir`（缺省 `drafts/`），文件名形态 `<日期>-<栏目 id>-<主题>.md`，
frontmatter 至少写 `title`；可选 `score` / `risk` / `style`（`style` 决定发布用的主题样式）。

## 4. 发布纪律

- **恒草稿**：所有通道只创建草稿，绝不自动发表。
- 派发与否由「生成后自动推送」开关（`autoPush.enabled`）决定；关着时如实汇报"未推送"。
- 平台列表是项目级配置（`platforms.default`）：这条流水线推哪些平台，与其它流水线无关。

## 5. 与引擎的接口（不要改，改的是上面那些）

| 你要做的   | 引擎要的                                                  | 在哪声明                                                                              |
| ---------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 一键生成   | `POST /generate`、`GET /status`、`GET /health`            | [`../.crosspost/project.json`](../.crosspost/project.json) 的 `capabilities.generate` |
| 定时到点跑 | `POST /slot/run`、`GET /slot/status`、`POST /slot/cancel` | 同上 `capabilities.schedule`                                                          |
| 槽位与时间 | 每个栏目的 `id` / `name` / `time` / `command`             | [`../.crosspost/schedule.json`](../.crosspost/schedule.json)                          |

provider 不用自己写：直接复用
[`examples/generate-provider-http/server.mjs`](../../generate-provider-http/server.mjs) 与
[`examples/slot-runner-http/server.mjs`](../../slot-runner-http/server.mjs)，
只需把"跑哪个脚本"指向本目录的 `scripts/generate.sh` 与 `scripts/run_once.sh`。
