# `preset/patches/` —— 对 DSH 安装目录的本地维护补丁

这里放**对 DSH 自身**（安装目录里的构建产物）打的本地补丁。它们不是 CrossPost 引擎的一部分，
也不属于 DSH 上游——每个补丁都必须：**可重放**（升级后被冲掉重跑一次即可）、**幂等**、
**可还原**、**失败要响**（版本漂移时明确报错，而不是悄悄改错地方）。

| 补丁                                                                       | 治什么                                                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| [`dsh-blank-session-command-nodes.sh`](dsh-blank-session-command-nodes.sh) | 全新**空会话**里敲斜杠指令（`/crosspost-status` 等）看不到结果——欢迎页把指令卡片盖住了 |

## 为什么会有这类补丁

DSH 的斜杠指令结果被渲染成**流程节点**，而聊天流程视图只在「存在非指令节点」时才算活跃；
客户端在「空会话且无活跃目标」时渲染**欢迎页**。于是空会话里执行指令时：
指令真的执行了（会话日志里有 `command/run` / `command/done`），但界面上没有任何变化。
空会话里跑 `/compact`、`/goal` 同样如此——是通用行为，不是某条指令坏了。

## 通用约定

- **位置**：补丁改的是 `<DSH 部署>/node_modules/<包>/lib/*.js` 这类**构建产物**，
  npx 重新安装或升级 DSH 会覆盖。所以每个补丁都必须在 `preset/upgrade-check.sh` 里有一条
  「补丁还在不在」的检查（用备份文件当"打过补丁"的标记），被冲掉时给出重放命令。
- **备份**：就地留一份 `<文件>.orig-before-crosspost-patch`，既当还原源，也当"已打过补丁"的标记。
- **安全**：替换前后做语法校验（把结果写成临时 `.mjs` 交给 `node --check`），
  坏了立刻回滚——绝不留下一个打不开的客户端。
- **匹配**：按上游**精确字符串**替换。匹配不到就报版本漂移并打印期望原文，让人重新定位，
  不做"猜着改"。
- **生效**：客户端产物由浏览器取，所以改完**刷新页面**即可（必要时硬刷新）。
